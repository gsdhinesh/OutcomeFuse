- (capability) CAP-1 Runtime Decision Policy - one justified/deny/stop decision before every unit of work, emitting policy_action plus decision_reason, and terminal_reason only where the run ends (F1)
- (capability) CAP-2 Outcome Contract - declarative, validated, immutable-per-run artifact declaring the quality floor, ceilings, reserve, tools, escalation and approval conditions (F2)
- (capability) CAP-3 Budget Ledger - allocated/spent/reserved/remaining in tokens and cost, protected verification reserve, per-mechanism attribution, affordability and marginal-value denial (F3)
- (capability) CAP-4 Quality Gate and sufficiency stop - binary pass/fail against mandatory criteria with mode qualifier, stop immediately on pass (F4)
- (capability) CAP-5 Loop Fuse - progress fingerprint per iteration, halt-no-progress recorded distinctly from exhaustion and sufficiency (F5)
- (capability) CAP-6 Tool Governor - canonical keys, run-scoped cache, duplicate and optional-call denial, side-effecting exclusion, enforced human approval with bounded timeout (F6)
- (capability) CAP-7 Context Governor - per-step evidence selection and compression into capsules preserving attributable facts verbatim; conditional, cut position 7 (F7)
- (capability) CAP-8 Model Governor - start on cheapest eligible model, escalate only on justified grounds, never breach the verification reserve, never silently; conditional, cut position 6 (F8)
- (capability) CAP-9 Preflight Planner - typed execution graph with per-step token and tool envelopes; consumes the contract classification, never owns it; conditional, cut position 8 (F9)
- (capability) CAP-10 Shadow mode - observe without enforcing, record executed ungoverned path plus estimated governed counterfactual with first divergence marked; synthetic and replayed workloads only in the MVP (F10)
- (capability) CAP-11 Integration surface - wrap an existing loop without re-architecture, OFF as an adapter state, two dissimilar host frameworks, conformance battery with out-of-band side-effect probe (F11)
- (capability) CAP-12 Decision record and audit trail - every decision recorded before it takes effect, queryable, exportable, sufficient to reconstruct why a run stopped without re-invoking a model (F12)
- (capability) CAP-13 Benchmark harness and evidence pipeline - frozen case set, repeated runs, per-mechanism ablation, proof card, overhead break-even study, reportability gates (F13)
- (capability) CAP-14 Side-by-side view - static generated replay of baseline and governed runs rendering the proof card, read-only, computes nothing; cut position 1 (F14)
- (capability) CAP-15 Gateway token metering - independent token counts through APIM, reconciled against governor self-report, self-reported label on fallback; cut position 10 (F15)
- (capability) CAP-16 Submission artifact - two-minute video covering problem, artifact, proof and scale, every figure traceable to an evaluation-set run (F16)
- (capability) CAP-17 Failure posture and degradation - advisors fail open and deregister, gate/ledger/approval-channel failures fail closed through the precedence ladder, shadow applies neither (PRD section 10)
- (capability) CAP-18 Data-class and retention governance - every run declares a data class with no default, non-synthetic persistence is refused outright, two-tier retention with content-free deletion receipts (FR109, NFR12)
- (constraint) Quality floor outranks the budget - the runtime exceeds a cost ceiling and requests a human rather than returning a cheaper answer that fails the contract (FR11, FR24)
- (constraint) Deterministic criterion-level validation is the authoritative gate; a model-judged rubric is advisory, cannot override a deterministic failure and cannot alone establish a pass (FR20)
- (constraint) A mandatory criterion must select an executable deterministic verifier from the closed project-owned registry; unverifiable criteria are advisory, never gating (FR8, AD-7)
- (constraint) The marginal-value estimator may only propose low-value; the Policy rejects any low-value proposal against an unmet mandatory criterion, so floor protection is not pluggable (FR17, AD-18)
- (constraint) No decision takes effect before it is recorded, and run state is a fold over the append-only decision log rather than an independent mutable structure (FR5, AD-2)
- (constraint) The governor core is pure - no I/O, clock, randomness or network; everything worldly is a port defined by the core (AD-1, AD-4)
- (constraint) One decision lane per run - verdicts are obtained strictly one at a time even where the host executes approved steps in parallel (AD-3)
- (constraint) Raw prompts, tool arguments and tool results never enter the decision log; only derived values, hashes and evidence-store references cross into the record (AD-5, NFR5, FR56)
- (constraint) One canonicalisation function serves every hash, with a specified versioned normalisation and exactly two admissible routes, each hashed artifact declaring its route id (AD-6)
- (constraint) A contract executes no code - safe loader only, declarative verifier selection, and no verifier performs I/O or reads run state (AD-7)
- (constraint) Rubric, answer keys, contracts, verifier registry, its tests and the coverage report are content-hashed and frozen in one operation before governor implementation begins (FR65)
- (constraint) Savings targets, counter-metric thresholds, minimum case counts and blind-review sample size are preregistered before any evaluation-set result is executed or inspected (FR66, FR102)
- (constraint) Calibration and evaluation case sets are separate artifacts; calibration results may never enter a headline figure or the submission (FR102)
- (constraint) Net is the only permitted headline; a headline figure requires its per-mechanism breakdown and a tool-call reduction requires its tool-suppression accuracy (FR61, FR62, FR70)
- (constraint) Conditional mechanisms are independently disableable and disabled means not registered - no mechanism carries an if-enabled branch (NFR10, AD-4)
- (constraint) No workload-specific logic in the governor core; workload specificity lives in contracts, tools and cases (NFR8)
- (constraint) Streaming is barred on the evidence path because gateway token counts are estimated when streaming is enabled (AD-10)
- (constraint) A host adapter produces no reportable run until it passes the conformance battery including the out-of-band side-effect probe (FR107, AD-15)
- (constraint) Shadow mode alters nothing the host would otherwise do and is exempt from fail-closed (FR91, AD-11)
- (constraint) A run whose data class is absent is refused, and anything other than synthetic refuses persistence of evidence and decision log alike until an approved production-data profile exists (FR109, AD-21)
- (constraint) Solo build inside a one-month window - any requirement not demonstrable in that window moves out of scope rather than being carried unmet (NFR11)
- (constraint) No credential appears in a contract and tool access runs under least-privilege identity (NFR7)
- (constraint) Tool-result reuse is run-scoped and process-local; no cross-run, cross-process or persistent cache exists (AD-14, NFR6)
- (constraint) Gate verdicts are binary pass or fail with no intermediate verdict; not-evaluated is the absence of a verdict carried in run state (FR94, FR105)
- (assumption) Primary persona and all four user journeys are inferred from builder judgment rather than research; two to three agent-owner interviews are in scope to confirm or correct them
- (assumption) The stop-when-sufficient white space rests on a survey rather than proof of absence; two of the closest commercial analogues were vendor-documentation only and unverified
- (assumption) Unmet-criterion targeting is assumed adequate as the MVP marginal-value estimator; its quality is unknown and the estimator is pluggable if it performs poorly
- (assumption) langgraph 1.2.11 declares classifiers only to Python 3.13 and is assumed to work on 3.14, pending validation before the adapter is committed
- (assumption) The seven-type verifier registry is assumed sufficient, with at most three deterministic additions admissible on demonstrated need before the freeze (AD-7, FR108)
- (question) Savings targets for net tokens, net cost and tool-call reduction are unset pending the overhead break-even study (FR67)
- (question) Counter-metric thresholds are unset and must be preregistered before any evaluation-set result is executed or inspected
- (question) Minimum case count per workload is unset (FR59)
- (question) Blind-review sample size per workload is unset (FR69)
- (question) The NFR1 decision-latency bound is unset and must be established against measured baseline step latency
- (question) Who authors the quality floor in a real deployment, and at what effort per task type - the main threat to the scale story
- (question) How a production deployment establishes ground truth without hand-authored answer keys; the deterministic gate degrades toward constraint-backed without them
- (question) An APIM instance on a tier that supports llm-token-limit is a critical-path dependency before any evaluation-set run; procurement status unresolved
