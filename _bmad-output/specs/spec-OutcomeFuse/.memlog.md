- (capability) CAP-19 Decision Stream Port - the library publishes every governor decision outward, one-way, as it is recorded, so any experience can consume it without the library knowing the experience exists (F17). Log append happens first, then the decision is enqueued. No subscriber is required; a slow subscriber is dropped and its channel closed with a terminal truncation signal; every published decision carries a monotonic per-run sequence so a client detects its own gaps. Success: a run with ten subscribers, one subscriber and none produces byte-identical decision logs and the same reported figures, and added latency is unchanged.
- (capability) CAP-20 Approval Port - a human authorises a contract-gated call across a same-host boundary; the only inbound path in the system and the only thing outside the library that can change a run (F18). One channel among several, never the only one - the scripted decider stays the harness's. Bounded minutes, the driver keeps the clock, authorisation bound to run_id and step_id and single-use. Success: FR100 exercises approve, deny, no-response under both on_timeout postures and channel-unavailable, each recording its distinct triple; a replayed or mismatched authorisation is refused; no client lifecycle event ever resolves a pause.
- (constraint) No experience ships inside the library - it holds no rendering code and no viewer process, and the wheel packages src/outcomefuse only. Nothing under src imports from clients. A client may subscribe to the published stream while a run executes but reads the decision log only once that run is sealed, and never touches the evidence store (AD-17, FR77).
- (constraint) The ports may serialize only types the record schema and the approval port already define - no wire-only DTO and no CONTENT field the record does not hold, so tool arguments and results are unpublishable by construction rather than by review. Envelope fields (sequence number, correlation id, approval authorisation) may cross provided each is boundary-generated, carries no run content and is never persisted as record. Publication is egress, so the non-synthetic refusal extends to it (AD-23, FR112, FR121).
- (constraint) Publication never blocks, delays or reorders governed execution and its cost is never governor overhead - watching a run must not change its number. A subscriber is dropped rather than allowed back-pressure, and nothing about a subscriber is written to the decision log because EventKind is closed and a viewer's health is not a fact about the run (AD-22, FR117, NFR1).
- (constraint) No transport or client event is ever an approval or a denial - a close, refresh, dropped connection, reconnect or crash resolves nothing, and an unanswered pause resolves only through the contract's on_timeout. The approval boundary is loopback same-host with a local token, and single-use is validated against recorded state rather than adapter memory so a restart cannot accept a replay (AD-24, FR113, FR114, FR118, FR119).
- (constraint) An interactively approved run is labelled human-approved AND unauthenticated-approval, is reportable only where its approval transcript was recorded, and satisfies re-executability by replaying that transcript through the scripted port. No governance, compliance or audit claim may rest on the recorded approver while the unauthenticated label applies (FR115, FR120, FR68).
- (assumption) Approver identity is self-asserted in the MVP and deliberately not verified. Same-host reach (loopback plus local token) is assumed to make that tolerable by putting the trust boundary at the machine, so the claim degrades to 'someone with access to this host said yes' rather than to nothing. Untested against any real deployment; a networked boundary would void it.
- (question) How does a production deployment establish a VERIFIED approver identity (PRD Q11)? The MVP records a claimed name and labels the run; the production move is an authenticated principal taking identity from the session and never from the payload. Blocks any non-synthetic use, which the data-class rule already refuses.
